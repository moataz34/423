## Critical Auto-Generated Files Explained

### 1. `xparameters.h` (Auto-Generated by Vivado)

**Location:** Created when you export hardware platform to Vitis

**What it contains:**
```c
/************************** Constant Definitions *****************************/

/*
 * Device ID definitions
 */
#define XPAR_SPI_ACCELEROMETER_0_DEVICE_ID 0
#define XPAR_TMRCTR_0_DEVICE_ID 1
#define XPAR_SCUGIC_SINGLE_DEVICE_ID 0

/*
 * Base addresses from Vivado block design
 */
#define XPAR_SPI_ACCELEROMETER_0_S00_AXI_BASEADDR 0x43C00000  // ← This is what you need!
#define XPAR_TMRCTR_0_BASEADDR 0x42800000
#define XPAR_SCUGIC_0_CPU_BASEADDR 0xF8F00100
#define XPAR_SCUGIC_0_DIST_BASEADDR 0xF8F01000

/*
 * Interrupt IDs
 */
#define XPAR_FABRIC_TMRCTR_0_VEC_ID 61
```

**Why it's critical:**
- Your `main.c` uses `XPAR_SPI_ACCELEROMETER_0_S00_AXI_BASEADDR` (line 20)
- This value is **NOT hardcoded** - Vivado assigns it based on your address map
- The name `SPI_ACCELEROMETER_0` comes from what you name the IP in the block design

**What you need to check:**
```c
// In your main.c:
#define SPI_ACCELEROMETER_BASEADDR      XPAR_SPI_ACCELEROMETER_0_S00_AXI_BASEADDR
                                       ↑
                        This must match the name in Vivado!
```

If you named it differently in Vivado (e.g., `my_spi_internal_0`), it would be:
```c
#define XPAR_MY_SPI_INTERNAL_0_S00_AXI_BASEADDR 0x43C00000
```

## Two-Layer Software Architecture

### Layer 1: Auto-Generated Low-Level Driver (Optional)

**Files:** `xspi_accelerometer.h`, `xspi_accelerometer_hw.h`

**Purpose:** Basic register read/write macros

**Example usage:**
```c
#include "xspi_accelerometer.h"

// Low-level register access
SPI_ACCELEROMETER_mWriteReg(XPAR_SPI_ACCELEROMETER_0_BASEADDR,
                    SPI_ACCELEROMETER_S00_AXI_SLV_REG0_OFFSET,
                    0x19);  // Write to control register
```

### Layer 2: Your Custom Driver (Higher-Level)

**Files:** `spi_accelerometer.h`, `spi_accelerometer.c` (in this repo)

**Purpose:** ADXL345-specific functions

**Example:**
```c
#include "spi_accelerometer.h"

// High-level ADXL345 functions
ADXL345_Init(XPAR_SPI_ACCELEROMETER_0_S00_AXI_BASEADDR);
ADXL345_ReadAccel(XPAR_SPI_ACCELEROMETER_0_S00_AXI_BASEADDR, &accel_data);
```

**Why two layers?**
- Auto-generated layer: Generic SPI register access
- Your custom layer: ADXL345 accelerometer specifics
- Separation allows reusing SPI IP for other SPI devices

## How Vivado Names Things

### Block Design Instance Name → XPAR Definitions

**In Vivado Block Design:**
```
When you add your IP to the block design, you give it an instance name:
┌─────────────────────┐
│  spi_accelerometer_0        │  ← Instance name (you choose this)
│  [SPI Accel v1.0]   │
└─────────────────────┘
```

**This generates in `xparameters.h`:**
```c
#define XPAR_SPI_ACCELEROMETER_0_DEVICE_ID              0
#define XPAR_SPI_ACCELEROMETER_0_S00_AXI_BASEADDR       0x43C00000
#define XPAR_SPI_ACCELEROMETER_0_S00_AXI_HIGHADDR      0x43C0FFFF
```

**Naming pattern:**
```
XPAR_<INSTANCE_NAME>_<INTERFACE>_<PARAMETER>
  ↓         ↓           ↓            ↓
XPAR_  SPI_ACCELEROMETER_0  _S00_AXI_  BASEADDR
```

### Common Instance Names

| Your Instance Name | Generated XPAR Name |
|-------------------|---------------------|
| `spi_accelerometer_0` | `XPAR_SPI_ACCELEROMETER_0_S00_AXI_BASEADDR` |
| `my_spi_internal_0` | `XPAR_MY_SPI_INTERNAL_0_S00_AXI_BASEADDR` |
| `axi_spi_0` | `XPAR_AXI_SPI_0_S00_AXI_BASEADDR` |

**In your code, update accordingly:**
```c
// main.c
#include "xparameters.h"

// Use the actual name from your Vivado design!
#define SPI_ACCELEROMETER_BASEADDR      XPAR_SPI_ACCELEROMETER_0_S00_AXI_BASEADDR
//                                    ↑↑↑↑↑↑↑↑↑↑↑↑↑
//                               MUST MATCH VIVADO INSTANCE NAME
```

## Complete Build Flow

### Step 1: Vivado - Create IP

```bash
1. Tools → Create and Package New IP
2. Create AXI4 Peripheral
3. Name: spi_accelerometer
4. Version: 1.0
5. Add interface: AXI4-Lite Slave (S00_AXI)
6. Edit IP:
   - Replace hdl files with yours
   - Add spi_internal.v
7. Package IP:
   - Optionally create driver files in drivers/ folder
   - Merge repository
```

### Step 2: Vivado - Block Design

```bash
1. Create block design
2. Add IP:
   - ZYNQ7 Processing System
   - AXI Timer
   - Your spi_accelerometer IP (name it: spi_accelerometer_0)
3. Run connection automation
4. Make external:
   - o_SPI_Clk → Right-click → Make External
   - i_SPI_MISO → Right-click → Make External
   - o_SPI_MOSI → Right-click → Make External
   - o_SPI_CS_n → Right-click → Make External
5. Add constraints: spi_accelerometer_constraints.xdc
6. Generate bitstream
7. Export hardware (include bitstream)
```

### Step 3: Vitis - Software

```bash
1. Create Platform Project
   - Import your .xsa hardware file

2. Platform generates:
   ├── xparameters.h          ← Contains XPAR_SPI_ACCELEROMETER_0_S00_AXI_BASEADDR
   ├── xspi_accelerometer.h           ← If you created drivers
   └── [other BSP files]

3. Create Application Project
   - Add your files to src/:
     • main.c
     • spi_accelerometer.h
     • spi_accelerometer.c

4. Verify includes work:
   #include "xparameters.h"   ← Auto-generated
   #include "xil_printf.h"    ← BSP
   #include "xscugic.h"       ← BSP (GIC driver)
   #include "xtmrctr.h"       ← BSP (Timer driver)
   #include "spi_accelerometer.h"     ← Your custom driver

5. Build and run
```

## What You Must Verify When Building

### ✓ Checklist:

1. **Vivado Instance Names Match**
   ```c
   // Check in Vivado block design
   Instance name: spi_accelerometer_0

   // Then in your code
   #define SPI_ACCELEROMETER_BASEADDR XPAR_SPI_ACCELEROMETER_0_S00_AXI_BASEADDR
   ```

2. **Base Address is Correct**
   ```c
   // Open xparameters.h after exporting from Vivado
   // Find the actual value:
   #define XPAR_SPI_ACCELEROMETER_0_S00_AXI_BASEADDR 0x43C00000

   // Your code should use this macro, not hardcode it!
   ```

3. **Timer and GIC Names Match**
   ```c
   #define TIMER_DEVICE_ID         XPAR_TMRCTR_0_DEVICE_ID
   #define INTC_DEVICE_ID          XPAR_SCUGIC_SINGLE_DEVICE_ID
   #define TIMER_INTERRUPT_ID      XPAR_FABRIC_TMRCTR_0_VEC_ID
   ```

4. **External Ports Match Constraints**
   ```tcl
   # In .xdc file
   set_property PACKAGE_PIN Y11 [get_ports o_SPI_Clk]

   # Vivado must have external port named exactly: o_SPI_Clk
   # (Vivado auto-names when you do Make External)
   ```

5. **SPI Signals Made External**
   ```
   In Vivado block design, you MUST right-click on:
   - o_SPI_Clk  → Make External
   - i_SPI_MISO → Make External
   - o_SPI_MOSI → Make External
   - o_SPI_CS_n → Make External
   ```

## Common Issues and Solutions

### Issue 1: "Undefined reference to `XPAR_SPI_ACCELEROMETER_0_S00_AXI_BASEADDR`"

**Cause:** xparameters.h not generated or wrong include path

**Solution:**
```bash
1. In Vitis, regenerate BSP:
   Right-click platform → Build

2. Check include paths:
   Project → Properties → C/C++ Build → Settings
   → Include paths should have: ../platform_project/.../bsp/include

3. Verify xparameters.h exists and contains your definition
```

### Issue 2: "Wrong base address / device not responding"

**Cause:** Instance name in Vivado doesn't match code

**Solution:**
```bash
1. Open Vivado block design
2. Check instance name (e.g., right-click on IP → Properties)
3. Update your code to match:
   #define SPI_ACCELEROMETER_BASEADDR XPAR_<ACTUAL_INSTANCE_NAME>_S00_AXI_BASEADDR
```

### Issue 3: "External ports not found in constraints"

**Cause:** Forgot to "Make External" in Vivado

**Solution:**
```bash
1. In Vivado block design
2. Right-click each SPI signal
3. Select "Make External"
4. Regenerate bitstream
5. Re-export hardware
```

### Issue 4: "Compilation errors - missing headers"

**Cause:** BSP not built or include paths wrong

**Solution:**
```bash
1. Right-click platform project → Build
2. Wait for BSP generation to complete
3. Right-click application → Build Project
```
